## Reading the numbers

- **Unavailable (rows = [], meta.status = "unavailable", with a reason)** — tables not yet in the live DB:
  `market/regime` (regime_daily), `groups/rrg` (group_daily), `deals/followthrough` (deal_session_net),
  `evidence/{setup}` (setup_outcomes), `research/*` (market_analogs, big_move_events, big_move_features,
  pre_move_watch), `stock/{sym}/analogs` (setup_outcomes). They switch to real data as soon as the tables exist.
- **Partial (real data, labelled fallback)**:
  - `desk/*` — queues computed live with the same predicate functions as the old desk (`squeeze_frame`,
    `classify_darvas_10ema_frame`) and `detect_contractions` for VCP, bounded to `as_of`; setup age / first-seen
    need `setup_daily`. Full counts, no display caps (old desk showed 40).
  - `groups/board`, `groups/{id}` — legacy `sector_rotation` + `sector_metrics_daily`; RS-Ratio/Momentum,
    quadrant and the floor dimension are NULL until `group_daily`.
  - `deals/session` — nets from collapsed prints (bulk ∩ block duplicates counted once); event type and
    persistence NULL until `deal_session_net`.
- **Latency** — everything reading stored tables is 50–1,200 ms cold. The live desk fallback is the slow path:
  first daily queue call ≈ 8–9 s (computes the as_of session and the previous one for New/Dropped), each extra
  daily queue ≈ 0.4 s (shared cache), weekly/monthly ≈ 13 s cold. Results are cached per latest-session
  fingerprint, so this is paid once per EOD session per process; it disappears once `setup_daily` is built.
  `desk/queues` counts only the daily timeframe unless `all_timeframes=true`.

## Schema assumptions the data-layer owner must reconcile

The services read these tables tolerantly (column aliases, missing columns → NULL) but were written against
spec §4.5 / §6.1 names:

- **regime_daily**: `trade_date`, `verdict` (Favourable/Constructive/Mixed/Weak/Danger), `prev_verdict`,
  `rule_id`, `days_in_state`, `changed_on`, `readings` (JSON text), and per pillar
  `<pillar>_status | _sentence | _dir_1d | _dir_1w | _dir_1m` for pillar ∈ trend, participation, leadership,
  follow_through, stress. Any other `<pillar>_*` column is returned under `pillars.<pillar>.inputs`; remaining
  columns under `inputs`.
- **group_daily**: `trade_date`, `level` (label e.g. "Industry" or snake_case), optional `floor`
  ('1000' | 'all' | 'watch'), `group_name`, `stock_count`, `rrg_quadrant`, `days_in_quadrant`, `rs_ratio`,
  `rs_momentum`, `rank`, `rank_delta_5/20/63`, `return_ew_21d`, `return_cw_21d`,
  `excess_vs_midsml400_21d/63d`, `excess_vs_nifty50_21d/63d`, `breadth_50`, `breadth_200`,
  `trend_template_pct`, `new_highs`, `turnover_share_5d/20d`, `turnover_share_delta`, `delivery_accumulation`,
  `deal_net_10s_cr`, `concentration_top3`. RRG tails sample every 5th stored session.
- **setup_daily**: `trade_date`, `queue` (darvas_squeeze | darvas_10ema | vcp), optional `timeframe`
  (D/W/M, default D), `symbol`, `trigger_price`, `stop_price`, `risk_pct`, `distance_to_trigger_pct`,
  `first_seen`, `status`, `features` (JSON: squeeze_pct, candle_range_pct, darvas_top/bottom, flavor,
  signal_date, contractions[], vdu_ratio, setup_age_sessions).
- **deal_session_net**: `trade_date`, `symbol`, `buy_cr`, `sell_cr`, `net_cr`, `buying_houses`, `vwap`,
  `vs_adv`, `deal_price_vs_close_pct`, `event_type`, `persistence_days`, `fii_net_cr`, `dii_net_cr`,
  `prop_net_cr`.
- **price_adjustments**: `symbol`, `ex_date`, `factor`, `kind`, `source`, `confidence`, `description`
  (the live table exists but is empty with INTEGER-typed text columns; the reader casts `symbol` to VARCHAR).
  `prices_daily.adj_*` columns are used via `COALESCE(adj_x, x)` when present.
- Evidence tables: `setup_outcomes` (`queue`, `signal_date`, `exit_date`, `r_multiple`, `hit_2r`, `mae_pct`,
  `mfe_pct`, `environment_state`, `group_quadrant`), `market_analogs`, `big_move_events` (`event_id`,
  `event_date`, `mcap_cr_at_event`), `big_move_features` (`event_id`), `pre_move_watch` (`trade_date`).
